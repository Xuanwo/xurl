# GitHub Copilot CLI Notes

## Status

Documented from:

- GitHub Docs for Copilot CLI
- Copilot CLI bundled README / schema files from a local `copilot` installation
- Local runtime inspection with an isolated real session generated by `copilot -p`

Validated locally with Copilot CLI `1.0.10` on 2026-03-23.

## What Matters for xurl

For xurl, GitHub Copilot CLI behaves like a session-event store plus a non-interactive JSON event stream:

- read/query source: local session-state files under the Copilot home directory
- write source: `copilot -p ... --output-format json`
- resume: `--resume <session_id>`
- role-like create: `--agent <agent>`

This is enough to support:

- `agents://copilot/<session_id>`
- `agents://copilot`
- `agents://copilot?q=...`
- `agents://copilot/<agent>` in write mode
- `agents://copilot/<session_id>` in append mode

## Local Storage Layout

The effective Copilot home root is:

1. `COPILOT_HOME`
2. `~/.copilot`

Observed local layout:

```text
~/.copilot/
  config.json
  logs/
  session-state/
    <session_id>/
      events.jsonl
      workspace.yaml
      checkpoints/index.md
```

Important notes:

- `events.jsonl` is the canonical persisted transcript for modern sessions.
- `workspace.yaml` is session index/context metadata, not the main transcript.
- The bundled runtime also contains legacy compatibility logic for `session-state/<session_id>.jsonl`.

## Persisted Event Shape

The bundled schema file is:

```text
~/Library/Caches/copilot/pkg/darwin-arm64/<version>/schemas/session-events.schema.json
```

The schema and local runtime confirm these persisted event families are relevant to xurl:

- `session.start`
- `session.resume`
- `session.model_change`
- `user.message`
- `assistant.message`
- `assistant.turn_start`
- `assistant.turn_end`
- `session.shutdown`

Observed message payloads that matter for xurl rendering:

- `user.message.data.content`
- `assistant.message.data.content`

Useful metadata fields:

- `session.start.data.sessionId`
- `session.start.data.context.cwd`
- `session.start.data.context.gitRoot`
- `session.start.data.context.branch`
- `session.resume.data.context.*`

## Output Stream for Non-Interactive Mode

Running Copilot non-interactively with:

```bash
copilot -p "..." --output-format json
```

produces a JSONL event stream on stdout.

Observed stream behavior:

- `assistant.message_delta` may appear before the final message
- `assistant.message` contains the final assistant text
- `result.sessionId` gives the session id even when earlier session lifecycle events are not emitted on stdout

This makes the write mapping straightforward:

```text
xurl create  -> copilot -p <prompt> --output-format json --allow-all-tools
xurl append  -> copilot -p <prompt> --output-format json --allow-all-tools --resume <session_id>
xurl role    -> copilot -p <prompt> --output-format json --allow-all-tools --agent <agent>
```

`--allow-all-tools` is required for non-interactive mode. xurl does not auto-add `--allow-all-paths` or `--allow-all-urls`; callers can pass them through query parameters when needed.

## Session Query Strategy

For query/discovery, xurl should scan `session-state/` and treat these as candidate transcripts:

- `session-state/<session_id>/events.jsonl`
- `session-state/<session_id>.jsonl` (legacy fallback)

Session id is the directory name or file stem.

Scope path should come from the latest available:

- `session.resume.data.context.cwd`
- fallback: `session.start.data.context.cwd`

Metadata for `--head` can be flattened from the first matching metadata event:

- `session.start`
- `session.resume`
- optionally `subagent.selected` when needed for agent context

## Custom Agents and Subagents

Copilot CLI clearly has agent-related concepts:

- command flag: `--agent`
- schema events: `subagent.started`, `subagent.completed`, `subagent.failed`, `subagent.selected`, `subagent.deselected`

Current xurl support intentionally stops short of child drill-down for Copilot:

- xurl supports role-like create via `--agent`
- xurl does not yet map Copilot `subagent.*` events into `agents://copilot/<main>/<child>` URIs

Reason:

- the schema proves agent activity exists
- current local evidence does not yet show a stable child transcript file layout comparable to Codex/Claude/OpenCode
- adding child URI support without that storage contract would be speculative

## Practical Implications for xurl

Current safe support boundary:

- read one main thread
- query provider threads
- query by path using `context.cwd`
- create a new Copilot conversation
- resume an existing Copilot conversation
- create with a named Copilot agent via role URI

Deferred work:

- expose Copilot subagent drill-down
- decide whether `workspace.yaml` should be surfaced directly in head output
- improve role-scoped query semantics using `subagent.selected` rather than plain text matching
